# 큐캐스트 (QueueCast)

2026 한국체육산업개발(주) 공공데이터 활용 경진대회 출품작 · 팀 33℃

올림픽공원 공연 관객이 야외에서 기다리는 시간대의 폭염·한파 위험을 3일 전부터 예보하고,
공단·주최사에는 단계별 대응 카드를, 관객에게는 도착·준비 안내(한·영)를 제공하는 웹 서비스.

- 데모: https://sseii.github.io/queuecast/
- 마감: 2026-12-01(화) 18:00 / 팀 목표: 12-01 오전 제출

## 동작 구조

```
기상청 단기예보 ─┐
KOPIS 공연목록 ──┼─▶ engine/ (체감온도·위험 단계 계산) ─▶ web/public/data/forecast.json ─▶ web/ (화면)
영문 공연정보 ───┤
편의시설 정보 ───┘
```

데이터 형식은 [`docs/JSON_형식.md`](docs/JSON_형식.md)를 기준으로 한다.

### 갱신 정책 (GitHub Actions)

| 시점 | 갱신 시각 (한국시간) | 내용 |

- cron은 UTC 기준: `30 20,23,2,5,8,11 * * *` (한국시간 05:30·08:30·11:30·14:30·17:30·20:30)
- 05:30·17:30 실행만 전체 갱신, 나머지 시각은 "오늘 공연이 있을 때만" 기상 갱신

## 폴더 구조

| 폴더 | 내용 | 담당 |
|---|---|---|
| `engine/` | 예보 엔진 (Python) | 수하 |

| `scripts/` | 공공데이터 내려받기·점검 스크립트 (kspo_check.py) | 팀장 |
| `docs/` | 기획서, 데이터 형식 문서, 그림(`docs/images/`) | 팀장 |

## 브랜치 규칙

- `main` 은 배포용. 직접 push 하지 않고 Pull Request 로 합친다.
- 각자 작업 브랜치: `engine`, `web`, `docs`
- 작업 시작 전 항상 `git pull origin main` 으로 main 최신 내용을 내 브랜치에 받는다.
- 작업 → commit → 자기 브랜치에 push → GitHub 에서 Pull Request → 한 명 이상 확인 후 merge
- 커밋 메시지: `타입(영역): 내용 (#이슈번호)` 예) `feat(engine): 체감온도 계산 추가 (#4)`
- Claude로 작업할 때도 같다: "engine(또는 web) 브랜치에 올리고 PR 만들어 줘"처럼 브랜치를 꼭 지정한다.

## 실행 방법

웹
```
cd web
npm install
npm run dev
```
브라우저에서 표시되는 주소(http://localhost:5173/queuecast/)로 접속.

엔진 (로컬 테스트)
```
cd engine
pip install -r requirements.txt
set DATAGOKR_KEY=본인_공공데이터포털_키
set KOPIS_KEY=본인_KOPIS_키
python forecast.py
```

## 데이터 이용 조건 (꼭 지킬 것)

| API | 제한 | 우리 사용량 | 지킬 것 |
|---|---|---|---|
| 기상청 단기예보 | 개발계정 일일 10,000건 | 하루 약 7건 | 한도 초과 오류(코드 22) 시 직전 예보 유지 |
| KOPIS | 초당 10회 이상 호출 시 서비스 중지, 출처 미표기 시 중단 | 하루 약 30건 | 호출 사이 `time.sleep(0.3)` 이상, 요청에 User-Agent 헤더 필수 |
| 영문 공연정보 | 포털 기준 | 하루 1건 | 05:30 실행에서만 조회 |

- 웹 화면 하단 출처 표기 (필수):
  `출처: (재)예술경영지원센터 공연예술통합전산망(www.kopis.or.kr), 한국체육산업개발(주)·국민체육진흥공단·기상청 공공데이터`
- 편의시설 정보는 2021년 조사 기준 → 화면에 "2021년 조사 기준" 표기

## 절대 하지 말 것

- API 키를 코드·커밋·단톡에 올리지 않는다. 키는 로컬 환경변수·`keys.json`(gitignore 처리)이나 GitHub Secrets(`DATAGOKR_KEY`, `KOPIS_KEY`)에만 둔다.
- 원천 CSV(입출차 등)를 커밋하지 않는다 (GitHub 파일 하나 100MB 제한). 분석 결과 요약 CSV·JSON만 올린다.
- 예보 생성에 실패했을 때 기존 forecast.json을 빈 파일이나 오류 내용으로 덮어쓰지 않는다.
